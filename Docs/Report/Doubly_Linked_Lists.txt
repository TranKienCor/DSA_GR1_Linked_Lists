3.2 Doubly Linked List (DLL) — Syllabus §4.1.2


• 1. Syllabus Placement: Chapter 4, Section §4.1.2 (Cormen et al. §10.2, pp. 236–238; Sedgewick §1.3, p. 146).


• 2. Learning Outcomes Served: Primary: LO2 (Algorithmic Trade-Offs) and LO3 (Real-World Systems).


• 3. Motivation & Problem Solved: 
	In a Singly Linked List, traversal is strictly unidirectional (forward-only). Deleting a specified node when given a direct pointer to it requires an O(N) forward search from the head to locate its predecessor. Furthermore, backward navigation is impossible. Doubly Linked Lists solve this by adding a secondary 'prev' pointer to every node, enabling bidirectional traversal and allowing true O(1) constant-time direct node removal and predecessor inspection.


• 4. Related Structures: 

	• Built upon: Singly Linked List with an additional backward reference pointer field ('prev').
	• Foundation for: Double-Ended Queues (Deques), LRU (Least Recently Used) Caches (paired with Hash Tables), Text Editor Cursor Buffers, and OS Process Schedulers.


• 5. When it is the WRONG Choice (Anti-Pattern): 
	
	A Doubly Linked List is the wrong choice in memory-constrained embedded systems or IoT devices where payload data per node is small. Storing two pointers ('next' and 'prev') per node consumes 16 bytes of pointer overhead on a 64-bit machine. If the payload is a 4-byte integer, memory density drops below 20%, resulting in prohibitive pointer storage overhead.


-->DLL SUMMARY: Doubly Linked Lists enable O(1) arbitrary node removal and full bidirectional navigation at the expense of doubling pointer memory overhead per node.
